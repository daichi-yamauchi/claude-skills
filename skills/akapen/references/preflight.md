# 出題前の試問 (preflight) — シートを開く前に、文脈ゼロの読者で試す

シートを書いた agent は題材の全文脈を頭に持っている。だから「これで伝わる」の自己判定は構造的に甘い。
そこで、人に見せる前に **何も知らない subagent にソースだけを渡して試問する**。この試問がシートの日本語検査も兼ねるので、別の検査を重ねない。

対象は 3 モードすべて。標準モードは**ソース (`<topic>-<NN>.akapen.md`)** を渡す (HTML は固定の CSS/JS で 30〜40KB 膨らむだけで、判定に要る情報はソースに全部ある)。指摘モードと添削モードは冒頭の問いブロックと導入文が対象 (原稿本文は人が直す対象なので試問しない)。

chat で聞く問い (絵の要らない問い) は試問しない。出題文をそのまま人が読むので、agent が自分で読み直せば足りる。

## 試問 5 問

検査員に渡すのは **ソースのパスと読者宣言 1 行だけ**。作業の経緯、元のコード、会話の文脈は渡さない。読者宣言は frontmatter の `reader:` をそのまま使う。

1. **選択肢の弁別** — 各 `q` について、それぞれの選択肢を選んだ場合の画面や挙動の違いを、このソースだけから説明せよ。続けて、見た目が違う選択肢に `fig:` の絵が付いているか答えよ (付いていない問いを挙げる)。絵は fig DSL の箱と矢印を読んで判定する
2. **引用の有無** — 各 `q` に `根拠:` (file:line か実行結果) が載っているか。載っていない問いを挙げよ
3. **実質 1 択の検出** — 推奨でない選択肢を選ぶ理由 (`利点:`) が読み取れるか。読み取れない問いを挙げよ
4. **音読と要約** — 本文 (結論・説明・図の title/caption・問い) を音読して不自然な文、意味の取れない文を逐語で挙げよ。続けて、30 秒で趣旨を 3 文で言え
5. **内輪語の列挙** — 読者宣言の許可語の外で、説明なしに使われている内輪語・作業語 (プロジェクトの中だけの呼び名、作業中に作った略語) や初見の造語を列挙せよ (`用語:` で定義済みの語は除く)。読者の分野の技術用語は列挙しない

## Agent ツールでの呼び方

`Agent` ツールで新しい subagent を立てる。`subagent_type` は general-purpose、`model` は `sonnet` (fork は文脈を引き継ぐので使わない)。**同期で結果を待つ (background にしない)。結果を受け取るまで応答を終えない。** description は「<topic>-<NN> 試問（赤ペンの読者検査）[sonnet]」の形。prompt の雛形:

```
次の Markdown は、人に判断を求める「赤ペン」のシートのソースです。あなたは何も知らない読者として読み、5 つの問いに答えてください。
ソース: /abs/path/to/akapen/<topic>-<NN>.akapen.md (Read で開く)
読者宣言: <frontmatter の reader: をそのまま>

ソースの読み方: ```fig ブロックは図で、node が箱 (id x y 幅 | 見出し、字下げ行が本文、red が提案の箱)、edge が矢印、mark が赤丸の番号です。```q ブロックが問いで、A* が推奨の選択肢、fig: が選択肢に付く絵の id です。

1. 各 q について、それぞれの選択肢を選んだ場合の画面や挙動の違いを、このソースだけから説明してください。説明できない問いは「説明不能」と書いてください。続けて、見た目が違う選択肢に fig: の絵が付いているか答え、付いていない問いを挙げてください。
2. 各 q に 根拠: (file:line か実行結果) がありますか。無い問いを挙げてください。
3. 推奨でない選択肢を選ぶ理由 (利点:) が読み取れますか。読み取れない問いを挙げてください。
4. 本文 (結論・説明・図の title と caption・問い) を音読して不自然な文、意味の取れない文を逐語で挙げてください。次に、このシートの趣旨を 30 秒で 3 文で言ってください。
5. 読者宣言の許可語の外で、説明なしに使われている内輪語・作業語 (プロジェクトの中だけの呼び名、作業中に作った略語) や初見の造語を列挙してください (用語: で定義済みの語は除く)。読者宣言にある分野の一般的な技術用語は、許可語に無くても列挙しないでください。

出力は問いごとに「通過 / 落ちた問いと理由」で。シートを直す提案は不要です。
```

## 判定と打ち切り

| 結果 | 扱い |
|---|---|
| 1〜3 で落ちた問いがある | 絵を加える / 問いを落とす / 言い換える (下の節)。直して build し直し、再試問 |
| 4 で不自然な文が挙がった | その文をほどく。3 文で趣旨が言えなかったら結論を書き直す |
| 5 の列挙が 3 語以上 | 内輪語を一般語に言い換えてから出題する。1〜2 語なら `用語:` で定義する。挙がったのが技術用語なら、シートを直さず `reader:` の許可語に足す |

添削モードは問いが 0 なので試問を省く。短いソース (1 画面程度) は 1 巡で打ち切ってよい。

再試問は **同じ検査員に差分だけを送って 1 回**。`SendMessage` で同じ agent に「直した箇所は X と Y。問い 1〜3 を再判定して」と送る。計 2 巡で打ち切る。

2 巡目の結果の読み方:

- 残ったのが軽微 (語彙 1〜2 語、語順、体言止め) なら、そのまま出題してよい
- 残ったのが重大 (意味の取れない文、選択肢の弁別不能、事実の矛盾) なら、3 巡目に進まない。読者宣言に戻ってソースを書き直す。検査で磨ける限界を超えているのは、書き手の側の問題だから

## 落ちた問いの直し方

- **絵を加える** — 選択肢 A と B の見た目の違いが説明できなかったら、`w=360` の fig を 2 枚並べて差分を `red` にし、`q` の `fig:` で結ぶ。動的な論点 (操作感、頻度) なら `./akapen/mock/` にモックを置き frontmatter の `mock:` で結ぶ
- **落とす** — 根拠が無い問いは「まだ調べ足りない問い」。自分で `file:line` か実行結果を調べて、事実で答えが決まるなら問いごと消す。人に残すのは決定だけ
- **言い換える** — 非推奨の選択肢に `利点:` が無かったら 1 行書き加える。それでも書けないなら実質 1 択なので、問いを落として推奨案で進める
- **内輪語を置き換える** — 注釈を加えるのではなく、一般語に置換する。どうしても要る語だけ `用語:` で 1 行定義する。読者の分野の技術用語は置換の対象外で、たとえ話や造語にしない
- **chat に移す** — 絵が要らない問いだった (方針・優先度) なら、シートから外して chat の ❓ にする
