# シートの規律 — 標準モードで何をどう書くか

見た目 (書体・7 色・幅・回答フォーム) は `assets/build.py` が固定で出す。ここには agent が書く内容の規律だけを置く。
指摘モード・添削モードには適用しない (原稿そのものを見せるのが定義)。

## 大原則: 読むのではなく、見て判断に到達するシート

承認のシートは、読ませて説得するシートではない。見て判断に到達するシートである。文章より、構造化された図と表のほうが「見て答えを入力しやすい」。

## 骨格 (ソースの順)

1. **frontmatter** — `title` は内容の要約ではなく言い切り
2. **結論:** — 3 文以内。ここで読むのをやめても判断に要る情報が揃う形。冒頭に大きな数字を並べる飾りは禁止。判断に要る数値は `q` の `数値:` に再掲
3. **用語:** — 読者が知らない語だけ 1 行ずつ。無ければ書かない
4. **全体図** (```fig) — 題材の全体像に、問いが刺さる場所の赤丸 ①②③ (`mark`)。問い 3 つ以上、または節 3 つ以上なら必須。人の採点で唯一「はっきり」勝った部品
5. **短い説明** — 現物スクショ (```shot) や再現はここ。変更点は ==赤の注記== で
6. **案の対比表** — 2 案以上 × 2 観点以上は表 1 枚。行 = 案、列 = 観点、セル 1〜2 文
7. **A/B の絵** (```fig w=360) — 選択肢の対立軸を両方絵にする。差分に赤 (`red` の箱・線)。`q` の `fig:` で結ぶと定義の位置には出ず、カードの選択肢の直下に出る (定義は q の直前に書いておくと読みやすい)
8. **問い** (```q) — 1 シート 4 問まで。カードの中に絵付きの選択肢と回答欄 (択一 / 保留 / 補足) があり、人はその場で答える。下まで戻らせない
9. **畳み付録** (```details) — 比較の詳細・落とした案・実測ログ。核心の判断材料は畳まない
10. **全体への赤ペン + [貼り付ける文章を作る]** — build が末尾に付ける

**問いをシートの先頭に置かない。** 問いを記憶したまま説明を読ませる形になる。判断への到達性は全体図と自己完結の問いカードで作る。

## 絵の規律

- **現物と乖離したモックを描かない。** 既存画面に加えるなら ```shot で現物を載せ、`mark` で赤の ①②③ を画像の上に乗せる
- **変更 = 赤 (`red`)、現状 = 無彩色。** 提案の箱と流れだけ赤にする。飾りに赤を使わない。シートから赤が消えると赤ペンに見えない
- **選択肢の対立軸は両方絵にする。** A と B の見た目の違いを小図 2 枚 (`w=360`) で描き、`q` の `fig:` で選択肢の直下に出す (絵は選ぶ瞬間に目の前にある)。推奨案の挿絵だけ並べて選択肢を文字 1 行にすると、人は想像で補えず全問お任せに倒れる。方針・優先度など見た目の無い選択肢には付けない
- 図には主張型の `title:` と「図 N — 何を見るか」の `caption:` を付ける。図とキャプションの拾い読みだけでも筋が追える形にする
- 図の文字は短く。箱の本文は 1 行 20 字前後が読みやすい (折り返すので消えはしないが、長いと箱が縦に伸びる)
- 再往復の 2 枚目以降は、前のシートで撤回した案を `~~取り消し線~~` で残す (何を捨てたかも情報)

## 問い (`q`) — 自己完結が条件

カードだけ読めばその場で答えられる形にする。本文へ戻らせない。

- 問い 1 行
- 各選択肢に `利点:` 1 行と `代償:` 1 行。**非推奨の選択肢にも利点を書く。** 代償しか無い選択肢は実質 1 択で、ゲートとして機能しない
- `数値:` に判断に要る数値を再掲
- 推奨 `*` を 1 つ。未回答 = お任せ = 推奨で確定
- `根拠:` に `file:line` か実行結果。事実を人に聞かない
- 「保留」は人が選ぶもので、agent が用意する選択肢ではない。保留が返ったら答えてから再掲する

## 文章の規律

- 1 段落 1 トピック、2〜4 文
- 読者が知らない内輪語・作業語は、一般語に言い換えるか `用語:` で 1 行定義してから使う
- 数値・時刻・パスは `` `等幅` ``
- **本文は判断に最小限、残りは畳む。** `details` の見出しは中身と分量を予告する文言 (例「検討して落とした 4 案と採点表 (表 1 枚)」)。「詳細」「その他」は禁止
- **核心の判断材料は畳まない。** 現物スクショ、選択肢の差分の絵、実測の要点は本文に出す

## build が固定で担うこと (agent は書かない)

書体 (IBM Plex Sans JP × Mono)・7 色トークン (赤 = 提案・訂正・論点、青 = 導線、残り無彩色)・本文幅 760px・問いカードの回答欄 (択一 / お任せ / 保留 / 補足) と末尾の全体への赤ペン + 貼り付ける文章を作る・下書きの localStorage 保存・図のレイアウト JS・印刷時の畳み展開 (回答欄は印刷に出ない)。
