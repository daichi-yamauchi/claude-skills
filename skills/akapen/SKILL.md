# akapen — 実装前の赤ペン先生 (ラウンド制)

作る前に、決めるべきことを人に決めてもらってから作るためのワークフロー。
**Input**: 題材 (UI 配置・設計・方針、または長文の原稿) と、そこに含まれる論点。
**Output**: ラウンドごとの問い (chat の ❓ と、ブラウザで開く HTML シート `./akapen/<topic>-<NN>.html`) → 人の回答 → 全論点が決まった時点の**確定サマリ**。実装はその後。
HTML 1 枚で自己完結する。ローカルでは `file://` で開き、人がこの機械のファイルを開けないクラウドのセッションでは Artifact で公開してリンクを渡す (`references/delivery.md`)。回答はどちらも貼り戻すだけ。

## 最重要禁則 (先に読む)

- **確定サマリに人が「進めて」と言う前に実装を始めない** — 回答が貼られても、まだ論点が残っていれば次のラウンド。設計と実装で人がモデルを切り替えられるよう、確定サマリで必ず止まる
- **HTML を直接書かない** — 標準モードのシートは `./akapen/<topic>-<NN>.akapen.md` (ソース) を書いて `assets/build.py` で生成する。固定の CSS/JS は build が埋める。旧テンプレ (sheet-template.html) は廃止
- **図の文字を SVG に書かない** — 図は `references/fig-dsl.md` の DSL で書く (文字は HTML、線は JS が引く)。生 SVG (```svg) は逃げ道で、使うと build が警告する
- **事実を人に聞かない** — 各問に `file:line` か実行結果を添える (`根拠:`)。人に残すのは決定 (好み・優先度・トレードオフの裁定) だけ。事実が要るならまず自分で調べる (subagent 可)
- **絵が要る問いと要らない問いを分ける** — UI 配置・構造・フロー・A/B の見た目差はシート (絵付き)。方針・命名・優先度・yes/no は chat の ❓ で聞く。絵が要る問いを chat で聞かない、絵の要らない問いをシートに載せない
- **シートは 1 ラウンド 4 問まで、chat は今答えられる問いを全部** — 人の判断コストはシート側の絵の読解にあるので、シートだけ絞る。chat の問いは grilling の型で数を絞らない
- **選択肢の対立軸は両方絵にする** — A と B の違いが絵で見えない問いをシートに出さない。`q` ブロックの `fig:` で選択肢の直下に絵が付く (問いカードがそのまま回答欄。人はその場で答える)
- **推奨の無い問いを出さない** — 未回答 = お任せ = 推奨で確定。人が決めずに済む形を保つ。ただし人が「保留」を選んだ問いは推奨で確定しない (質問に答えて次のラウンドで再掲)
- **正解が一意で自己検証できることは聞かない** — 好みや曖昧な仕様が左右する判断だけ
- **長文の読み物を要約したシートに組み直さない** — 指摘モードか添削モードで原稿そのものを見せる

## モード選択

| モード | 対象 | 人がすること | 使うもの |
|---|---|---|---|
| **標準** (迷ったらこれ) | UI 配置・設計・方針。ラウンド制 | chat の ❓ に答える + シートの問いカードに答える (択一 / お任せ / 保留) + 全体への赤ペン | `assets/build.py` + `references/source-format.md` |
| **指摘** (shiteki) | 記事・README・長文。直すのは agent | 原稿そのままの体裁で段落にチップ + ひとこと | `assets/shiteki/README.md` |
| **添削** (tensaku) | 人が本文を直接書き換える長文 | HTML 内で段落を編集して完成形を返す | `assets/tensaku/README.md` |

3 モードとも [貼り付ける文章を作る] が `references/reply-format.md` の固定形を出す。ボタン文言は変えない。

## 手順 (標準モード)

> **assets のパス**: この SKILL.md があるディレクトリ基準。`~/.claude/skills/akapen/` または `${CLAUDE_PLUGIN_ROOT}/skills/akapen/`。以下 `<skill>` と書く。

1. **論点ツリーを作る** — 決めるべきことを列挙し、「A が決まらないと B は聞けない」の依存で並べる。**フロンティア** = 前提が全部決まっていて今聞ける問い。頭の中でよい (長ければ `./akapen/<topic>-tree.md` に書く)
2. **事実を調べる** — フロンティアの問いに要る事実 (現状のコード・実測・スクショ) を自分で集める。事実で答えが決まる問いはツリーから消す
3. **ラウンドを組む** — フロンティアを 2 つに分ける。絵が要る問い → シート (4 問まで、超えたら依存の浅い順に次ラウンドへ)。絵が要らない問い → chat。シートが 0 問なら chat だけのラウンドでよい (その場合 4〜5 は飛ばす)
4. **シートのソースを書く** — `./akapen/<topic>-<NN>.akapen.md` を `references/source-format.md` の書式で。図は `references/fig-dsl.md`。書き方の規律は `references/sheet-rules.md`。`python3 "<skill>/assets/build.py" ./akapen/<topic>-<NN>.akapen.md --check` で警告を潰してから `-o ./akapen/<topic>-<NN>.html` で生成
5. **試問 (preflight)** — `references/preflight.md` の手順で、文脈ゼロの subagent に**ソース (.akapen.md) のパス**と読者宣言だけ渡す (HTML は渡さない — 大きいだけで判定に要らない)。`Agent` は同期で待つ。落ちた問いを直して再 build。計 2 巡で打ち切る
6. **出題して待つ** — 1 つのメッセージで (a) chat の問いを grilling の型で並べ、(b) シートを人に届けて案内文を出し、応答を終える。chat の問いの型:
   ```
   ❓ **Q5** - **見出し**: 問い本文 (選択肢があれば列挙)
   ➡️ 推奨: <案> — <理由 1 行>
   ```
   番号はシートの問 (Q1〜) と通しにする (シートが Q1〜Q3 なら chat は Q4〜)。シートの届け方は 2 つ、**人がこの機械のファイルを開けるか**で選ぶ (手順と案内文は `references/delivery.md`):
   - **ローカル** — `open ./akapen/<topic>-<NN>.html`
   - **クラウド** (人がこの機械のファイルを開けない) — `--hosted` で build し直して `Artifact` ツールで公開し、URL を伝える
   どちらも「chat の Q4〜 はこの返信にそのまま書いてください」を添える
7. **反映して次のラウンド** — 貼られた【赤ペン回答】と chat の回答を `references/reply-format.md` の規則で読む。お任せ → 推奨で確定。**保留 → その場で質問に答え、次ラウンドのシートか chat に同じ問いを再掲する** (推奨で確定しない)。決定でツリーの前提が埋まり、新しいフロンティアが出る。次のシートは `-<NN+1>.akapen.md` にコピーして差分編集 (撤回した案は `~~取り消し線~~` で残す)。フロンティアが空になるまで 3〜7 を繰り返す
8. **確定サマリで止まる** — フロンティアが空になったら、chat に次を出して**応答を終える**:
   ```
   ## 確定サマリ
   - 決定: Q1 → A (…) / Q2 → B (…) / …  (ラウンドをまたいで全部)
   - 保留への回答: …
   - 触るファイル: path:line の一覧 (作る・変える・消す)
   - 残る前提・未決 (あれば)
   実装に進むなら「進めて」と返してください。設計と実装でモデルを変えるなら、ここで /model を切り替えてから。
   ```
   「進めて」が来るまで実装しない。修正が来たらサマリを直して再提示
9. **証跡** — `.akapen.md` と `.html` は消さずに残す (git 管理下ならシートの commit を推奨)。反映後のコード・原稿の commit は人に確認してから

## Gotchas

- **build の警告を無視しない** — 問が 5 以上 / 根拠なし / 推奨なし / fig 参照切れ / 箱が右端を超える / 生 SVG。`--check` で潰してから生成する
- **`open` が無いだけの環境と、クラウドは別物** — 人が同じ機械にいるなら絶対パスと `file://` URL を渡せば足りる。人がこの機械のファイルを開けないなら `file://` は届かないので、Artifact で公開する
- **クラウドで公開するとシートの中身が外に出る** — クライアント名・`file:line`・スクショが載る。外に出せない題材では絵の要る問いを落として chat だけで回すか、ローカルで作業するときまで持ち越す。判断はユーザーに聞く
- **公開するシートは `--hosted` で build する** — 付け忘れるとモックのボタンが `file://` のまま開けないリンクになる (モックが無いシートでは差は出ない)
- **試問の Agent を background で立てない** — 結果を読まずに人へ出すことになる
- **label はシートごとに一意** (`part4-01`, `part4-02`)。回答 1 行目の【赤ペン回答】ラベルと localStorage の下書きキーになる。使い回すと別シートの下書きが復元される
- **図の座標は箱の左上と幅だけ** — 高さと線の座標を書き足しても無視される (ブラウザで実測する)。箱が伸びたぶんは下の行が自動で下がる
- **選択肢の絵は `fig:` で参照する** — 図を 2 回書かない。`fig:` で結んだ図は定義の位置には出ず、カードの選択肢の直下にだけ出る
- **保留を推奨で確定しない** — `(保留) 質問: …` の行は「まだ決めていない」。答えてから再掲する
- **長文モードの原稿は往復中に凍結する** — 指摘のアンカーはブロック番号、添削の差分の土台は生成時の記事。直すなら `-02` を作り直す
- **クリップボード自動コピーは環境により失敗する** — textarea 表示が正。人が選択してコピーすれば足りる
