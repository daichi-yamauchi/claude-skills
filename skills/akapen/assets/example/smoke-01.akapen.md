結論: 一覧の並べ替えは、行そのものをつかんで動かす形にする。矢印ボタンは行が増えると押す回数が増える。決めたいのは操作の形と保存の間の 2 点。

用語:
- 行 — 一覧の 1 件分の横並び
- 下書き — まだ保存していない並び順

## 行をつかんで動かす

行が 20 件を超えると、矢印ボタンでは 1 つ動かすのに何度も押すことになる。つかんで動かす形なら 1 回で済む。代わりに、細い画面では指が滑って誤って動かすことがある。

```fig ab-1a w=360 fs=10.5
title: A. 行をつかんで動かす
caption: A — 遠くへ動かすのが 1 回で済む
node row 8 26 200 | 行をつかむ
  長押ししてから動かす
node drop 8 84 200 red | 離した場所に入る
  途中の行は自動でよける
edge row:b -> drop:t
```

```fig ab-1b w=360 fs=10.5
title: B. 矢印ボタンで 1 つずつ動かす
caption: B — 誤操作が起きにくい。遠くへ動かすと回数が増える
node row 8 26 200 | 行の右端のボタン
  上へ / 下へ
node move 8 84 200 | 1 回押すと 1 つ動く
  20 件先へ動かすと 20 回
edge row:b -> move:t
```

| 案 | 遠くへ動かす | 細い画面での誤操作 |
|---|---|---|
| A. つかんで動かす | 1 回で済む | 指が滑ると動いてしまう |
| B. 矢印ボタン | 件数ぶん押す | 起きにくい |

```q
問 1. 並べ替えの操作をどの形にするか
A* 行をつかんで動かす | 利点: 遠くへ動かすのが 1 回で済む | 代償: 細い画面で誤って動かすことがある | fig: ab-1a
B  矢印ボタンで 1 つずつ | 利点: 誤操作が起きにくく、読み上げにも乗る | 代償: 20 件先へ動かすと 20 回押す | fig: ab-1b
根拠: src/list/Rows.tsx:64 は現在どちらの操作も持たない。一覧の件数は最大 40 件
数値: 1 件動かすのに A は 1 操作、B は移動距離と同じ回数
```

```q
問 2. 保存の API をいつ呼ぶか
A* 保存ボタンを押したとき | 利点: 保存前なら取り消せる | 代償: 押し忘れると並びが消える
B  動かすたび | 利点: 押し忘れが起きない | 代償: 動かすたびに通信し、取り消せない
根拠: src/api/order.ts:20 の保存は配列を丸ごと受け取るので、どちらでも API は変わらない
```

